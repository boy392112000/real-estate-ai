# 專案工程與架構開發規範 (Engineering Standards)

本規範強制約束本專案的所有開發、重構與維護工作：

1. **零假資料與防幻覺 (Zero Fake Data)**：
   - 絕不在任何文字輸出、介面顯示或資料傳遞中使用虛構數據或「精選好房」等假佔位符。
   - 所有資料嚴格源自使用者輸入或官方即時聯網數據。

2. **測試驅動開發與連續驗證 (TDD & CI/CD)**：
   - 所有功能修改或擴充必須具備對應測試。
   - 每次修改後必須執行 `docker compose exec app python -m pytest`，確保 100% 通過。

3. **SOLID 原則與避免過度設計 (KISS / YAGNI)**：
   - 單一職責、開閉原則、里氏替換、介面隔離、依賴反轉。
   - 嚴禁三層以上無效包裝，不進行過早最佳化。

4. **架構尊重與協同討論先行 (Architecture Respect)**：
   - 新功能或架構重構前，必須先與使用者對齊設計。
   - 嚴格沿用專案既有的命名風格、檔案組織與資料模型。

5. **純淨 Docker 環境與用戶端金鑰隱私 (Clean Docker & Client Privacy)**：
   - 伺服器零環境金鑰留存，一切依賴用戶端傳入。
   - 地端環境零污染，全在 Docker 容器內編排。

6. **Git 版本控制規範 (Git Commit Standards)**：
   - Git Commit 提交訊息必須**一律使用繁體中文**清晰描述修改內容與原因（例如：`功能: ...`、`修復: ...`、`重構: ...`）。
